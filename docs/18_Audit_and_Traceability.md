# Audit and Traceability

# Одит и проследимост

## Въведение

Модулът **Audit and Traceability** реализира централизирана система за регистриране на важните събития в платформата **Industrial Digital Twin Platform**.

Неговата основна цел е да осигури пълна проследимост на инженерните действия, извършвани от потребителите, както и възможност за последващ анализ, контрол и одит на всички ключови операции.

Всеки запис съдържа информация за:

- извършеното действие;
- потребителя;
- засегнатия обект;
- техническите параметри на заявката;
- времето на изпълнение.

По този начин платформата осигурява прозрачност и надеждна история на инженерните процеси.

---

# Основни цели

Модулът има следните цели:

- проследяване на действията на потребителите;
- регистриране на ключови инженерни операции;
- подпомагане на административния контрол;
- осигуряване на проследимост на цифровите двойници;
- съхраняване на техническа информация за заявките;
- подпомагане при анализ на възникнали проблеми;
- създаване на надеждна история на инженерните процеси.

---

# Основен модел

Одитната информация се съхранява чрез модела:

```text
AuditLog
```

Всеки запис представлява едно събитие в системата.

---

# Структура на AuditLog

Всеки одитен запис съдържа следните основни полета.

| Поле | Описание |
|------|----------|
| user | Потребителят, извършил действието |
| action | Тип на действието |
| entity_type | Тип на бизнес обекта |
| entity_id | Идентификатор на бизнес обекта |
| details | Допълнителна информация в JSON формат |
| ip_address | IP адрес на клиента |
| computer_name | Име на клиентския компютър |
| user_agent | Информация за браузъра |
| created_at | Дата и час на събитието |

---

# Поддържани действия

Моделът използва следните типове действия.

| Код | Значение |
|------|----------|
| LOGIN | Вход в системата |
| LOGOUT | Изход от системата |
| CREATE | Създаване |
| UPDATE | Редактиране |
| DELETE | Изтриване |
| RESEARCH | Външно AI проучване |
| ANALYZE | Локален AI анализ |
| APPROVE | Одобряване |
| REJECT | Отхвърляне |
| EXPORT | Експортиране |

---

# Работен процес

```text
Потребител
      │
      ▼
Извършване на действие
      │
      ▼
Събиране на информация
      │
      ▼
Създаване на AuditLog
      │
      ▼
Запис в базата данни
      │
      ▼
Административен преглед
```

---

# Одит при работа с цифровите двойници

При операции върху цифровите двойници могат да бъдат регистрирани:

- създаване;
- редактиране;
- изтриване;
- промяна на статус;
- други инженерни операции.

За всяка операция се съхраняват:

- потребител;
- тип действие;
- идентификатор на цифровия двойник;
- IP адрес;
- браузър;
- дата и час.

---

# Одит при създаване на производен цифров двойник

При успешно създаване на производен цифров двойник платформата създава отделен AuditLog запис.

Записът съдържа:

- идентификатор на инженерния експеримент;
- идентификатор на оригиналния цифров двойник;
- идентификатор на производния цифров двойник;
- каталожен номер;
- брой приложени промени;
- брой ръчни инженерни промени;
- брой копирани файлове.

Примерната JSON структура е:

```json
{
    "operation": "create_from_experiment",
    "experiment_id": "...",
    "source_twin_id": "...",
    "result_twin_id": "...",
    "result_part_number": "...",
    "applied_change_count": 1,
    "manual_change_count": 2,
    "copied_file_count": 3
}
```

---

# Допълнителни данни

Полето

```text
details
```

се реализира като JSON структура.

То позволява различните модули на платформата да записват специфична информация без необходимост от промяна на структурата на базата данни.

В него могат да се съхраняват:

- идентификатори;
- параметри;
- резултати;
- приложени промени;
- инженерни бележки;
- статистическа информация.

---

# IP адрес

Всеки одитен запис може да съдържа IP адреса на клиента.

При локална работа това позволява разграничаване на различните работни станции в мрежата.

---

# Име на компютъра

Когато е налично, платформата съхранява името на клиентския компютър.

Тази информация подпомага администратора при диагностика на възникнали проблеми.

---

# User-Agent

В полето

```text
user_agent
```

се записва информация за клиента.

Тя включва:

- браузър;
- версия;
- операционна система;
- тип устройство.

---

# Дата и час

Всеки запис автоматично получава времеви маркер чрез:

```text
created_at
```

Записите се подреждат по подразбиране в низходящ ред.

Най-новите събития се показват първи.

---

# Индекси

За оптимизиране на производителността моделът използва индекси върху:

```text
created_at
```

```text
entity_type + entity_id
```

```text
user + action
```

Това позволява бързо филтриране и търсене в големи журнали.

---

# Административен панел

Одитните записи са регистрирани в Django Admin.

За всеки запис се визуализират:

- дата;
- потребител;
- действие;
- тип на обекта;
- идентификатор;
- IP адрес.

Поддържат се:

- търсене;
- филтриране;
- сортиране.

---

# Полета само за четене

Всички основни полета на AuditLog са конфигурирани като Read Only.

Това включва:

- user;
- action;
- entity_type;
- entity_id;
- details;
- ip_address;
- computer_name;
- user_agent;
- created_at.

По този начин се предотвратява редактиране на вече създадени записи.

---

```text
        │
        ▼
Одобряване на предложения

        ▼
Създаване на производен цифров двойник
```

# Ограничения

Настоящата версия:

- използва Django Admin за преглед;
- не поддържа отделен потребителски интерфейс за одита;
- не архивира автоматично старите записи;
- не реализира криптографско подписване на журналите.

# Заключение

Модулът **Audit and Traceability** реализира централизирана система за регистриране на всички ключови инженерни действия в Industrial Digital Twin Platform. Чрез съхраняване на информация за потребителя, извършеното действие, засегнатия обект и техническите параметри на заявката платформата осигурява надеждна проследимост, административен контрол и възможност за последващ анализ на инженерните процеси.
