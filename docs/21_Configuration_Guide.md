# Configuration Guide

# Ръководство за конфигуриране

## Въведение

Настоящият документ описва конфигурирането на **Industrial Digital Twin Platform** след успешното инсталиране на системата.

Конфигурацията определя начина, по който платформата работи, използваните AI модели, достъпа до външните AI услуги, локалния AI анализ, файловата система и настройките на Django.

Всички конфигурационни параметри могат да бъдат променяни без необходимост от промяна на програмния код.

---

# Конфигурационни файлове

Основните настройки се съхраняват в следните файлове:

```text
.env
```

```text
config/settings.py
```

```text
requirements.txt
```

---

# .env файл

Всички чувствителни настройки се съхраняват във файла:

```text
.env
```

Типичен пример:

```text
SECRET_KEY=your-secret-key

DEBUG=True

ALLOWED_HOSTS=127.0.0.1,localhost

OPENAI_API_KEY=

ANTHROPIC_API_KEY=

GEMINI_API_KEY=

GROK_API_KEY=

OLLAMA_MODEL=llama3
```

Файлът **не трябва** да бъде публикуван в публични Git репозитории.

---

# Django настройки

Основните настройки на приложението се намират във файла:

```text
config/settings.py
```

Там се конфигурират:

- INSTALLED_APPS;
- MIDDLEWARE;
- DATABASES;
- TEMPLATES;
- STATICFILES;
- MEDIA;
- AUTHENTICATION;
- LOGGING.

---

# DEBUG режим

По време на разработка:

```python
DEBUG = True
```

При производствена среда:

```python
DEBUG = False
```

---

# ALLOWED_HOSTS

Примерна конфигурация:

```python
ALLOWED_HOSTS = [
    "127.0.0.1",
    "localhost",
    "industrial.dtp",
]
```

При работа във вътрешна мрежа могат да бъдат добавени допълнителни локални адреси.

---

# База данни

Настоящата версия използва SQLite.

Конфигурацията се намира в:

```python
DATABASES
```

Основният файл е:

```text
db.sqlite3
```

При необходимост архитектурата позволява преминаване към PostgreSQL без промени в бизнес логиката.

---

# Статични файлове

Настройките включват:

```python
STATIC_URL
```

```python
STATICFILES_DIRS
```

```python
STATIC_ROOT
```

Тези директории съдържат:

- CSS;
- JavaScript;
- изображения;
- Three.js библиотеките.

---

# Медийни файлове

Конфигурират се чрез:

```python
MEDIA_URL
```

```python
MEDIA_ROOT
```

В директорията **media** се съхраняват:

- STL файлове;
- STEP файлове;
- изображения;
- документи;
- допълнителни файлове.

---

# Локален AI

Използваният модел се определя чрез:

```text
OLLAMA_MODEL
```

Пример:

```text
OLLAMA_MODEL=llama3
```

При необходимост моделът може да бъде заменен с друг локално инсталиран модел.

---

# OpenAI

Конфигурацията се извършва чрез:

```text
OPENAI_API_KEY
```

При липса на ключ платформата автоматично пропуска OpenAI анализа.

# Anthropic

ANTHROPIC_API_KEY

# Google Gemini

Конфигурацията се извършва чрез:

```text
GEMINI_API_KEY
```

---

# xAI Grok

Конфигурацията се извършва чрез:

```text

```

# Работа без външен AI

Ако всички API ключове останат празни:

- външният AI анализ няма да бъде използван;
- локалният AI анализ чрез Ollama ще продължи да работи нормално.

# Three.js

Библиотеките за 3D визуализация се намират локално в проекта.

Не се използват външни CDN услуги.

По този начин 3D визуализацията работи и без интернет.

---

# Преводи

Настройките за превод използват два независими текста:

- оригинален английски;
- преведен български.

Преводите се записват в базата данни и могат да бъдат визуализирани чрез бутоните:

- **Покажи на български**
- **Покажи оригинала**

---

# Локална мрежа

При използване във вътрешна мрежа се препоръчва:

```text
industrial.dtp
```

като локално DNS име.

Това позволява платформата да бъде достъпна чрез:

```text
http://industrial.dtp
```

вместо чрез IP адрес.

---

# Права за достъп

Всички потребители използват стандартната Django Authentication система.

Препоръчва се:

- отделен административен профил;
- отделни инженерни профили;
- индивидуални пароли.

---

# Архивиране

При промяна на конфигурацията е препоръчително архивиране на:

```text
.env
```

```text
db.sqlite3
```

```text
media/
```

---

# Проверка на конфигурацията

След приключване на конфигурирането трябва успешно да работят:

- вход в системата;
- цифровите двойници;
- инженерните експерименти;
- локалният AI анализ;
- външният AI анализ (ако са конфигурирани API ключове);
- преводите;
- качването на файлове;
- 3D визуализацията.

---

# Добри практики

Препоръчва се:

- файлът `.env` да не се публикува;
- да се използват силни пароли;
- редовно архивиране на базата данни;
- архивиране на директорията `media`;
- използване на отделни потребителски акаунти;
- работа в локална защитена мрежа.

---

# Бъдещо развитие

Предвидени са следните подобрения:

- конфигурация чрез административния панел;
- автоматична проверка на настройките;
- множество конфигурационни профили;
- централизирано управление на AI моделите;
- поддръжка на PostgreSQL;
- Docker конфигурация;
- автоматична диагностика на конфигурацията.

---

# Заключение

Правилната конфигурация на **Industrial Digital Twin Platform** гарантира стабилна работа на всички функционални модули, сигурно локално съхранение на инженерната информация и коректна интеграция с външните и локалните AI модели. Архитектурата позволява лесно адаптиране към различни инженерни среди без необходимост от промени в програмния код.
