# Installation Guide

# Ръководство за инсталация

## Въведение

Настоящият документ описва процеса по инсталиране, конфигуриране и първоначално стартиране на **Industrial Digital Twin Platform**.

Платформата е разработена като локално Django приложение и е предназначена за използване както в развойна среда, така и в реална производствена инфраструктура.

Всички инженерни данни, цифрови двойници, файлове, експерименти и резултати от локалния AI анализ се съхраняват локално.

---

# Системни изисквания

## Операционна система

Поддържат се:

- Windows 10;
- Windows 11;
- Ubuntu Linux 22.04+;
- Debian Linux;
- други Linux дистрибуции с Python 3.12+.

---

## Софтуер

Необходимо е да бъдат инсталирани:

- Python 3.12 или по-нова версия;
- Git;
- Ollama;
- Visual Studio Code (препоръчително);
- Web Browser (Chrome, Edge или Firefox).

---

# Клониране на проекта

Изтегляне на проекта:

```bash
git clone https://github.com/<repository>.git
```

Преминаване в директорията:

```bash
cd Industrial_Digital_Twin_Platform
```

---

# Създаване на виртуална среда

## Windows

```bash
python -m venv .venv
```

Активиране:

```bash
.venv\Scripts\activate
```

---

## Linux

```bash
python3 -m venv .venv
```

Активиране:

```bash
source .venv/bin/activate
```

---

# Инсталиране на зависимостите

```bash
pip install -r requirements.txt
```

След приключване на инсталацията всички необходими Python библиотеки са готови за използване.

---

# Конфигуриране на .env

В основната директория се създава файл:

```text
.env
```

Примерна конфигурация:

```text
SECRET_KEY=your-secret-key

DEBUG=True

OPENAI_API_KEY=

ANTHROPIC_API_KEY=

GEMINI_API_KEY=

GROK_API_KEY=

OLLAMA_MODEL=llama3
```

При липса на външни AI услуги съответните API ключове могат да останат празни.

---

# Създаване на базата данни

Изпълняват се миграциите:

```bash
python manage.py migrate
```

---

# Създаване на администратор

```bash
python manage.py createsuperuser
```

Попълват се:

- потребителско име;
- e-mail;
- парола.

---

# Стартиране на Ollama

Преди използване на локалния AI трябва да бъде стартирана услугата.

```bash
ollama serve
```

При необходимост се изтегля желаният модел:

```bash
ollama pull llama3
```

или друг поддържан модел.

---

# Стартиране на платформата

По време на разработка:

```bash
python manage.py runserver
```

След стартиране платформата е достъпна на:

```text
http://127.0.0.1:8000
```

---

# Производствено стартиране

За демонстрации и използване извън развойната среда се препоръчва използване на WSGI сървър.

Например:

## Waitress (Windows)

```bash
waitress-serve --listen=0.0.0.0:8000 config.wsgi:application
```

## Gunicorn (Linux)

```bash
gunicorn config.wsgi:application
```

Така не се използва Django Development Server.

---

# Достъп чрез локално име

При използване на локален DNS или файла **hosts** платформата може да бъде достъпна например чрез:

```text
http://industrial.dtp
```

вместо

```text
http://127.0.0.1:8000
```

Това улеснява използването по време на демонстрации и работа във вътрешна мрежа.

```text
Industrial_Digital_Twin_Platform/
│
├── config/
├── apps/

├── docs/

├── static/

```

---

# Проверка на инсталацията

След стартиране трябва успешно да работят:

- вход в системата;
- библиотеката с цифрови двойници;
- инженерните експерименти;
- локалният AI анализ;
- външният AI анализ (при налични API ключове);
- инженерните предложения;
- преводите;
- качването на файлове;
- 3D визуализацията.

# Актуализиране на проекта

Обновяване на сорс кода:

```bash
git pull
```

```bash
pip install -r requirements.txt
```

```bash
python manage.py migrate
```

---

# Отстраняване на проблеми

## Ollama не стартира

Проверка:

```bash
ollama serve
```

---

## Липсва модел

Изтегляне:

```bash
ollama pull llama3
```

---

## Липсват зависимости

Повторно изпълнение:

```bash
pip install -r requirements.txt
```

---

## Проблем с миграциите

Изпълнение:

```bash
python manage.py migrate
```

---

## Не могат да се заредят STL моделите

Проверява се:

- наличието на STL файл;
- директорията `media`;
- правилният път до файла.
