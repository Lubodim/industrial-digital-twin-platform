# Administrator Guide

# Ръководство за администратора

## Въведение

Настоящият документ описва административните функции на **Industrial Digital Twin Platform**.

Администраторът отговаря за управлението на потребителите, цифровите двойници, инженерните експерименти, файловете, материалите, производствените технологии и общата конфигурация на платформата.

Освен това администраторът следи за правилното функциониране на системата, извършва архивиране и контролира достъпа до инженерната информация.

---

# Основни отговорности

Администраторът има следните основни задачи:

- управление на потребителите;
- управление на цифровите двойници;
- управление на материалите;
- управление на производствените технологии;
- управление на инженерните експерименти;
- управление на файловете;
- наблюдение на AI услугите;
- архивиране на информацията;
- следене на одитния журнал.

---

# Вход в административния панел

Административният панел е достъпен чрез:

```text
/admin/
```

След успешен вход се зарежда стандартният Django Administration Panel.

---

# Управление на потребителите

Администраторът може да:

- създава потребители;
- редактира потребители;
- деактивира потребители;
- променя пароли;
- определя административни права;
- управлява разрешенията.

---

# Управление на цифровите двойници

От административния панел могат да бъдат:

- създавани;
- редактирани;
- активирани;
- деактивирани;
- изтривани.

Администраторът има достъп до всички цифрови двойници независимо от техния собственик.

---

# Управление на материалите

Администраторът управлява каталога с материали.

Поддържат се операции:

- създаване;
- редактиране;
- изтриване;
- активиране;
- деактивиране.

---

# Управление на производствените технологии

Могат да бъдат управлявани:

- CNC обработка;
- 3D печат;
- леене;
- лазерно рязане;
- фрезоване;
- струговане;
- други технологии.

---

# Управление на инженерните експерименти

Администраторът може да:

- разглежда всички експерименти;
- следи статуса им;
- проверява заключените експерименти;
- анализира инженерните разговори;
- преглежда AI резултатите.

---

# Заключени експерименти

При необходимост администраторът може да провери:

- кой инженер е заключил експеримента;
- кога е заключен;
- кога изтича заключването.

Това позволява диагностика при възникнали проблеми.

---

# Управление на файловете

Администраторът има достъп до всички качени файлове.

Поддържат се:

- преглед;
- изтриване;
- проверка на описанието;
- проверка на типа;
- проверка на свързания цифров двойник.

---

# Управление на изображенията

Администраторът може да проверява:

- основното изображение;
- STL файловете;
- STEP файловете;
- допълнителните инженерни документи.

---

# Наблюдение на AI услугите

Администраторът следи:

- OpenAI;
- Claude;
- Gemini;
- Grok;
- Ollama.

При необходимост могат да бъдат проверени:

- API ключовете;
- локалният модел;
- настройките.

---

# Работа с локалния AI

Преди използване на локалния анализ трябва да бъде стартирана услугата:

```bash
ollama serve
```

При необходимост може да бъде инсталиран нов модел:

```bash
ollama pull llama3
```

или друг поддържан модел.

---

# Управление на преводите

Администраторът може да проверява:

- оригиналните AI резултати;
- преведените версии;
- статуса на превода.

При необходимост преводите могат да бъдат генерирани повторно.

---

# AuditLog

Администраторът има достъп до одитния журнал.

Могат да бъдат разглеждани:

- входове;
- изходи;
- редакции;
- инженерни експерименти;
- AI анализи;
- създадени производни цифрови двойници.

---

# Архивиране

Препоръчително е периодично архивиране на:

```text
db.sqlite3
```

```text
media/
```

```text
data/
```

```text
.env
```

---

# Актуализиране на системата

При обновяване на проекта се изпълняват:

```bash
git pull
```

След това:

```bash
pip install -r requirements.txt
```

При необходимост:

```bash
python manage.py migrate
```

---

# Проверка на системата

След обновяване трябва да бъдат проверени:

- входът в системата;
- библиотеката с цифрови двойници;
- инженерните експерименти;
- локалният AI анализ;
- външният AI анализ;
- преводите;
- файловете;
- STL визуализацията.

---

# Работа в локална мрежа

Платформата може да бъде използвана чрез:

```text
http://127.0.0.1:8000
```

или

```text
http://industrial.dtp
```

при използване на локален DNS или hosts файл.

---

# Добри практики

Препоръчва се:

- използване на отделен административен акаунт;
- архивиране преди всяка актуализация;
- периодична проверка на AuditLog;
- използване на индивидуални потребителски акаунти;
- периодично архивиране на файловете;
- проверка на работата на Ollama.

---

# Отстраняване на проблеми

## Не стартира платформата

Проверете:

- виртуалната среда;
- зависимостите;
- миграциите;
- файла `.env`.

---

## Не работи локалният AI

Проверете:

```bash
ollama serve
```

---

## Не работи външният AI

Проверете:

- API ключовете;
- интернет връзката;
- настройките във файла `.env`.

---

## Не се визуализира STL модел

Проверете:

- наличието на STL файл;
- директорията `media`;
- правилния път до файла.

Административният панел на **Industrial Digital Twin Platform** предоставя централизирано управление на всички основни компоненти на системата.
