# Testing Strategy

# Стратегия за тестване

## Въведение

Настоящият документ описва стратегията за тестване на **Industrial Digital Twin Platform**.

Основната цел е да се гарантира, че всички функционални модули работят коректно както самостоятелно, така и като част от цялостната система.

Тестването обхваща както функционалността на потребителския интерфейс, така и бизнес логиката, AI модулите, управлението на файловете, локалната база данни и взаимодействието между отделните компоненти.

---

# Цели на стратегията

Основните цели са:

- валидиране на функционалните изисквания;
- откриване на програмни грешки;
- проверка на взаимодействието между модулите;
- валидиране на AI анализа;
- проверка на сигурността;
- проверка на производителността;
- проверка на локалната работа;
- гарантиране стабилността на платформата.

---

# Видове тестване

При разработката са използвани следните видове тестване:

- Unit Testing;
- Integration Testing;
- Functional Testing;
- User Acceptance Testing;
- Manual Testing;
- Regression Testing;
- Performance Testing.

---

# Обхват на тестването

Тестването обхваща следните основни модули:

- Authentication;
- Digital Twins;
- Materials;
- Technologies;
- File Management;
- Experiments;
- External AI;
- Local Ollama Analysis;
- Engineering Proposals;
- Translation System;
- Derived Twin Creation;
- 3D Visualization;
- Audit.

---

# Unit Testing

Unit тестовете проверяват отделните компоненти независимо един от друг.

Тестват се:

- модели;
- услуги;
- помощни функции;
- бизнес логика;
- валидиращи механизми.

Основната цел е да се гарантира коректността на всеки компонент преди интеграцията му с останалата система.

---

# Integration Testing

Интеграционното тестване проверява взаимодействието между отделните модули.

Проверяват се:

- обменът на данни;
- комуникацията между услугите;
- последователността на бизнес процесите;
- работата на базата данни.

---

# Functional Testing

Функционалното тестване валидира всички функции, достъпни за потребителя.

Проверяват се:

- създаване на цифров двойник;
- редактиране;
- качване на файлове;
- стартиране на експеримент;
- AI анализ;
- инженерни предложения;
- създаване на производен цифров двойник.

---

# User Acceptance Testing

Провежда се ръчно тестване от гледна точка на крайния потребител.

Проверява се:

- лесна навигация;
- коректност на интерфейса;
- разбираеми съобщения;
- правилна последователност на действията;
- удобство при работа.

---

# Regression Testing

След всяка значителна промяна се извършва повторно тестване на вече реализираните функционалности.

Основната цел е да се гарантира, че новите промени не нарушават вече работещ код.

---

# Performance Testing

Проверява се производителността при:

- работа с голям брой цифрови двойници;
- множество файлове;
- големи STL модели;
- продължителни инженерни разговори;
- AI анализи.

---

# Тестване на удостоверяването

Проверяват се:

- вход;
- изход;
- отказан достъп;
- невалидни потребители;
- защитени страници.

Очакван резултат:

Само удостоверени потребители могат да използват платформата.

---

# Тестване на цифровите двойници

Проверяват се:

- създаване;
- редактиране;
- активиране;
- деактивиране;
- изтриване;
- визуализиране;
- филтриране;
- търсене.

---

# Тестване на файловете

Проверяват се:

- качване;
- визуализиране;
- изтриване;
- наследяване при производен цифров двойник.

Поддържаните файлове включват:

- STEP;
- STL;
- PNG;
- PDF;
- DOCX.

---

# Тестване на инженерните експерименти

Проверяват се:

- създаване;
- заключване;
- отключване;
- режим Read Only;
- инженерен разговор;
- работа при повече от един потребител.

---

# Тестване на външния AI

Проверяват се:

- изпращане на заявки;
- получаване на резултати;
- обработка при грешки;
- работа без API ключ;
- работа при недостъпна услуга.

---

# Тестване на локалния AI

Проверяват се:

- стартиране на Ollama;
- локален анализ;
- обработка на инженерния разговор;
- генериране на предложения;
- записване в базата данни.

---

# Тестване на преводите

Проверяват се:

- автоматично създаване на превод;
- визуализиране на български;
- визуализиране на английски;
- повторно използване на вече генериран превод.

---

# Тестване на инженерните предложения

Проверяват се:

- показване;
- одобряване;
- отхвърляне;
- записване на статуса;
- превключване между езиците.

---

# Тестване на производните цифрови двойници

Проверяват се:

- създаване;
- наследяване на информацията;
- прилагане на одобрените предложения;
- история на промените;
- връзка с оригиналния модел.

---

# Тестване на 3D визуализацията

Проверяват се:

- зареждане на STL модел;
- въртене;
- мащабиране;
- преместване;
- синхронизиране на двата прозореца;
- визуализация на производните цифрови двойници.

---

# Тестване на AuditLog

Проверяват се:

- записване на действията;
- потребител;
- дата;
- IP адрес;
- тип действие;
- допълнителни данни.

---

# Интеграционен сценарий

Основният сценарий на платформата включва:

```text
Създаване на цифров двойник
          │
          ▼
Инженерен експеримент
          │
          ▼
Външен AI анализ
          │
          ▼
Локален AI анализ
          │
          ▼
Инженерни предложения
          │
          ▼
Одобряване
          │
          ▼
Производен цифров двойник
          │
          ▼
3D визуализация
```

Всеки етап се валидира самостоятелно и като част от общия процес.

---

# Критерии за успешно тестване

Функционалността се счита за успешна, когато:

- няма програмни грешки;
- данните се записват коректно;
- интерфейсът работи правилно;
- AI анализите приключват успешно;
- файловете се обработват правилно;
- производните цифрови двойници се създават успешно;
- всички основни сценарии завършват без грешки.

---

# Ограничения

Настоящата стратегия не включва:

- автоматизирано натоварващо тестване;
- penetration testing;
- distributed testing;
- cloud deployment testing.

Тези дейности са предвидени като бъдещо развитие.

---

# Бъдещо развитие

Планирани са:

- автоматични Unit тестове;
- автоматични Integration тестове;
- Selenium UI тестове;
- CI/CD тестове чрез GitHub Actions;
- Performance тестове;
- Security тестове;
- Load тестове;
- автоматично генериране на тестови отчети.

---

# Заключение

Избраната стратегия за тестване осигурява систематична проверка на всички основни компоненти на **Industrial Digital Twin Platform**. Комбинирането на модулно, интеграционно, функционално и потребителско тестване гарантира надеждна работа на платформата и стабилност на инженерния процес при управление на цифрови двойници и използване на изкуствен интелект.
