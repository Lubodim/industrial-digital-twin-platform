# Troubleshooting

# Отстраняване на проблеми

## Въведение

Настоящият документ описва най-често срещаните проблеми при работа с **Industrial Digital Twin Platform**, възможните причини за възникването им и препоръчителните начини за тяхното отстраняване.

Документът е предназначен както за крайни потребители, така и за системни администратори.

---

# Платформата не стартира

## Симптом

След изпълнение на:

```bash
python manage.py runserver
```

платформата не се стартира.

## Възможни причини

- виртуалната среда не е активирана;
- липсват Python зависимости;
- липсва `.env` файл;
- има грешка в настройките.

## Решение

Активирайте виртуалната среда:

```bash
.venv\Scripts\activate
```

Инсталирайте зависимостите:

```bash
pip install -r requirements.txt
```

Проверете файла:

```text
.env
```

---

# Не могат да бъдат изпълнени миграциите

## Симптом

При изпълнение на:

```bash
python manage.py migrate
```

се появява грешка.

## Възможни причини

- повредена база данни;
- липсващи миграции;
- конфликт между миграциите.

## Решение

Проверете:

```bash
python manage.py showmigrations
```

След това:

```bash
python manage.py migrate
```

---

# Не може да се влезе в системата

## Симптом

Потребителят не може да се удостовери.

## Възможни причини

- неправилно потребителско име;
- неправилна парола;
- потребителят е деактивиран.

## Решение

Проверете потребителя в административния панел.

При необходимост сменете паролата чрез:

```bash
python manage.py changepassword <username>
```

---

# Не работи локалният AI

## Симптом

Локалният анализ не стартира.

## Възможни причини

- Ollama не работи;
- моделът не е инсталиран;
- неправилна конфигурация.

## Решение

Проверете:

```bash
ollama serve
```

След това:

```bash
ollama list
```

При липса на модел:

```bash
ollama pull llama3
```

или друг използван модел.

---

# Не работи външният AI

## Симптом

Външният AI анализ приключва с грешка.

## Възможни причини

- липсва интернет;
- невалиден API ключ;
- недостъпна AI услуга.

## Решение

Проверете:

- интернет връзката;
- API ключовете във файла `.env`;
- конфигурацията на съответния AI доставчик.

---

# AI анализът е прекалено бавен

## Симптом

Локалният анализ продължава значително по-дълго от очакваното.

## Възможни причини

- голям инженерен разговор;
- голям брой AI резултати;
- слаб процесор;
- използване на голям езиков модел.

## Решение

Изчакайте приключването на анализа.

При необходимост използвайте по-лек локален модел.

---

# Не се визуализира 3D модел

## Симптом

В страницата на цифровия двойник няма 3D визуализация.

## Възможни причини

- няма качен STL файл;
- STL файлът липсва;
- файлът е повреден.

## Решение

Проверете дали към цифровия двойник е качен STL файл.

При необходимост качете нов.

---

# 3D моделът е прекалено голям или малък

## Симптом

Моделът не се побира във визуализатора.

## Възможни причини

- различни единици при експортиране;
- неправилен мащаб.

## Решение

Експортирайте STL файла отново с правилните размери.

Платформата автоматично центрира модела, но не може да коригира неправилно експортирани единици.

---

# Липсва бутон за 3D визуализация

## Симптом

Не се показва бутонът за визуализиране.

## Възможни причини

- няма STL файл;
- цифровият двойник няма свързени файлове.

## Решение

Качете STL файл към цифровия двойник.

---

# Не могат да се качват файлове

## Симптом

Качването приключва с грешка.

## Възможни причини

- липсват права;
- директорията `media` не е достъпна;
- файлът е прекалено голям.

## Решение

Проверете:

- правата върху директорията `media`;
- свободното дисково пространство;
- размера на файла.

---

# Производният цифров двойник не се създава

## Симптом

След приключване на анализа не се създава нов цифров двойник.

## Възможни причини

- няма одобрени предложения;
- инженерният експеримент е невалиден;
- възникнала е грешка при копиране на файловете.

## Решение

Проверете дали има поне едно одобрено инженерно предложение.

След това повторете операцията.

---

# Не се превеждат AI резултатите

## Симптом

Продължава да се показва английският текст.

## Възможни причини

- преводът все още не е приключил;
- възникнала е грешка при превода.

## Решение

Изчакайте няколко секунди и презаредете страницата.

След успешното генериране преводът се използва автоматично при следващи отваряния.

---

# Не работи превключването между езиците

## Симптом

Бутоните за смяна на езика не реагират.

## Възможни причини

- липсва преведен текст;
- страницата не е обновена.

## Решение

Презаредете страницата.

Ако преводът вече е наличен, смяната на езика ще бъде мигновена.

---

# Не може да се редактира инженерен експеримент

## Симптом

Полетата са заключени.

## Възможни причини

- експериментът е заключен от друг инженер;
- потребителят няма необходимите права.

## Решение

Проверете кой е заключил експеримента.

Изчакайте отключването или използвайте друг експеримент.

---

# Не работи инженерният чат

## Симптом

Не може да бъде изпратено ново съобщение.

## Възможни причини

- експериментът е заключен от друг потребител;
- експериментът е в режим само за четене.

## Решение

Заключете експеримента със собствения си потребителски профил.

---

# Липсват изображения

## Симптом

Изображението на цифровия двойник не се визуализира.

## Възможни причини

- липсва PNG файл;
- изображението е изтрито.

## Решение

Качете ново изображение.

---

# Статистиката не се зарежда

## Симптом

Картичките със статистика показват празни стойности.

## Възможни причини

- проблем при заявката към базата данни;
- липсващи данни.

## Решение

Проверете наличието на цифрови двойници и рестартирайте приложението.

---

# Платформата работи бавно

## Симптом

Страниците се зареждат по-бавно от очакваното.

## Възможни причини

- голяма база данни;
- множество едновременни AI анализи;
- ограничени хардуерни ресурси.

## Решение

Затворете неизползваните експерименти и проверете системното натоварване.

---

# Проверка на логовете

При възникване на неочаквана грешка проверете:

- конзолата на Django;
- логовете на Ollama;
- системните съобщения;
- административния панел.

---

# Добри практики

За предотвратяване на проблеми се препоръчва:

- редовно архивиране;
- използване на актуална версия на Python;
- използване на последната версия на Ollama;
- периодично обновяване на зависимостите;
- редовно архивиране на базата данни;
- използване на локална защитена мрежа.

---

# Кога да се потърси помощ

Препоръчително е да се потърси съдействие при:

- повредена база данни;
- невъзможност за стартиране на платформата;
- липса на достъп до административния панел;
- загуба на инженерни данни;
- системни грешки, които не могат да бъдат възпроизведени.

---

# Заключение

Повечето проблеми при работа с **Industrial Digital Twin Platform** могат да бъдат отстранени чрез проверка на конфигурацията, локалните AI услуги, файловата система и базата данни. Благодарение на модулната архитектура и локалното изпълнение диагностиката е лесна, а възстановяването на нормалната работа обикновено изисква минимални административни действия.
